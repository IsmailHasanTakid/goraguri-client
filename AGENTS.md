## Project layout

- Next.js 16.4.3 App Router, React 19.3, TypeScript (strict), Tailwind CSS v4. Single app, npm (`package-lock.json`); not a monorepo.
- App code lives in `src/app`; `@/*` maps to `src/*`. Feature components go in `src/app/components/<area>/` (e.g. `home/Navbar.tsx`), imported as `@/app/components/home/Navbar` — they are not routes. Only `page`/`layout`/`route` files create routes.
- `README.md` is stale `create-next-app` boilerplate; trust `package.json` and `next.config.ts`.
- Sibling `../tourist-server` (Express + MongoDB, port 5000) is the intended API, but it is unfinished and nothing in this client calls it yet. There is no API layer or env file here.

## Next.js specifics

- `cacheComponents: true` and `partialPrefetching: true` enable the new caching model: data reads are uncached by default, and `"use cache"` + `cacheLife`/`cacheTag` opt in. Read `node_modules/next/dist/docs/01-app/01-getting-started/08-caching.md` before adding data fetching; pre-16 `fetch` cache/revalidate assumptions do not apply.
- `reactCompiler: true` — components are auto-memoized; avoid reflexive `useMemo`/`useCallback`.
- Tailwind v4 is CSS-first: there is no `tailwind.config.*`. Theme tokens are defined in `src/app/globals.css` under `@theme inline`; CSS is wired through the `@tailwindcss/turbopack` loader in `next.config.ts`.
- Route types such as `LayoutProps<"/">` are global generated types, not imports. `next-env.d.ts` is ignored by `.gitignore` and regenerated by `next dev`/`next typegen`.
- `experimental.agentFeedback` is on, so `next dev` rewrites the `nextjs-agent-rules` block above. Leave that block in place.
